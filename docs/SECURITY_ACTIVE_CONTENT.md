# Пассивное открытие документов — проверка 2026-10-24, v0.8.0-rc.4

## Что подтверждается

LiteOffice не предоставляет исполнение скриптов/макросов из документов ни при
открытии, ни при просмотре. Нет кнопки «Enable content» и скрытого режима запуска.
Все допустимые расширения — DOC, DOCX, XLS, XLSX, PDF, TXT, MD, RTF — читаются как данные.
Не заявляется, что файл безопасен для других программ или очищен от вложений.

| Формат | Путь чтения | Активное содержимое |
|---|---|---|
| TXT / MD | ограниченный UTF-8/UTF-16 текст → egui TextEdit | Нет HTML/Markdown renderer, shell, обработчиков ссылок или исполнения блоков кода. |
| RTF | собственный ограниченный текстовый разбор, без RichEdit/Office | Пропускаются object/objdata/pict, инструкции полей и неизвестные starred destinations. Нет OLE/DDE, макросов или запуска содержимого. Save As строит отдельный RTF только из текста. |
| DOC | CFB, main-story CLX, картинки, видимый результат полей | VBA/OLE не активируются. DDE/field instructions не исполняются; видимый кеш результата остаётся текстом. HTTP(S)-гиперссылку можно открыть лишь явным нажатием; javascript/file-ссылки отвергаются. |
| DOCX | ZIP/XML, текст, размеры шрифта, PNG/JPEG | VBA, скриптовые и OLE-части не загружаются как код; внешние image relationships не загружаются. При Save As неизвестные части сохраняются как байты, а не исполняются. |
| XLS | calamine, CFB/BIFF, worksheet_range | Нет Excel Automation, VBA/XLM runtime или пересчёта формул. Используются сохранённые значения ячеек; macro streams не исполняются. |
| XLSX | ZIP/XML, внутренние worksheets, cached values | Формулы не вычисляются; внешние/выходящие из пакета worksheet relationships отвергаются. VBA/вложения не активируются; calcChain/defined-name auto-open не исполняются. |
| PDF | bounded memory stream → Windows.Data.Pdf → PNG → egui texture | Нет browser/WebView, Acrobat automation, JS engine, dispatch OpenAction/AA/Launch/URI, интерактивных форм или распаковки/запуска вложений. В приложение передаётся только растр страницы. |

Принимаются только эти расширения; DOCM/DOTM/XLSM/XLAM/JS/VBS/PS1/HTA/CMD/HTML/EXE,
включая `document.pdf.js`/`document.docx.exe`, не открываются как документы.
Обычный `.doc`/`.xls` сам по себе может содержать макросы — это не проверка
отсутствия макросов, а отсутствие их исполнения в LiteOffice.

## Просмотр кода и точек запуска

Дополнение rc.21: `src/text_document.rs` реализует пассивный импорт TXT/MD/RTF.
`src/pdf_print.rs` печатает неизменяемый снимок открытого PDF через Windows.Data.Pdf
в PNG. `pdf_print_windows.ps1` получает только созданные программой растры и
геометрию; PDF-байты, JavaScript, вложения и действия ему не передаются.
Встроенный helper запускается только после явного запроса печати пользователя.

- `src/file_ops.rs` — общий whitelist для диалогов/CLI/drop.
- `src/doc.rs` — ограниченное чтение CFB, CLX и пассивная фильтрация полей;
  HTTP(S)-ссылка — единственное разрешённое внешнее действие и только по клику.
- `src/docx.rs` — ZIP/XML/raster; ссылки изображений разрешаются внутри ZIP.
- `src/xls.rs` — только `worksheet_range`, без вызовов macro/formula interpreter.
- `src/xlsx.rs` — кеши ячеек; явная проверка TargetMode/worksheet part path.
- `src/pdf.rs`, `src/pdf_view.rs` — файловый буфер и native bitmap API, только
  page count/size/render. PDF-действия не преобразуются в команды или UI-события.
- `src/startup.rs` запускает лишь текущий exe по явному запросу нового окна;
  путь документа передаётся отдельным OS-native аргументом, не shell-строкой.
- Печать офисного документа по явному Print/Ctrl+P использует собственный
  встроенный PowerShell-helper. Это код программы, НЕ скрипт документа. Данные
  документа передаются отдельным base64-манифестом и рисуются DrawString/bitmap,
  не подставляются в ScriptBlock/Invoke-Expression. При Open этот helper не запускается.
- В зависимостях нового reader нет VBA/JavaScript/browser движка. Дополнен
  `windows 0.62.2` с узкими PDF/Streams/WinRT features; runtime PDF встроен в ОС.

Первый эксперимент с уже кешированной windows-привязкой 0.52 воспроизвёл abort
на формировании текста ошибки повреждённого PDF (старый null-slice путь в HRESULT
formatting, выявленный текущим Rust). Не отключались проверки и не скрывалась
ошибка: новый reader использует современную windows 0.62.2, а тот же broken-PDF
тест после замены проходит. Старые транзитивные версии других зависимостей не
переписывались ради этой функции.

## Фактически выполненные проверки

- Office synthetic fixtures: дополнительные VBA/JS/CMD части в DOCX, VBA storage
  в CFB DOC/XLS, VBA/script части XLSX, DDEAUTO field instruction с безопасным
  локальным sentinel. Открытие/Save As не создали marker; результат поля — текст.
  Это синтетические активные данные, не полный набор подписанных VBA/XLM проектов.
- XLS BIFF FORMULA содержит `1+1`, но сохранённый кеш — `142`: получено `142`,
  а не пересчитанное `2`. XLSX WEBSERVICE-formula возвращает только сохранённый
  текст. Внешние/file/traversal worksheet relationships отвергаются.
- PDF fixtures с JavaScript OpenAction/Names и Launch action: страницы читаются
  как картинки, растр совпадает с инертным вариантом, локальный marker не создан,
  исходные PDF побайтно неизменны. Скрипт-sentinel безвреден и находится только
  в тестовой папке; вручную не запускать `.cmd` и не открывать fixture в другом PDF-приложении.
- Неверный заголовок, повреждённый PDF, >64 MiB, неверные размеры/индекс страницы
  возвращают ошибки; неудачный PDF Open не теряет несохранённый DOCX.
  Дополнительная property-проверка нашла округление 2000 → 2001 px при некоторых
  дробных размерах страниц: исправлено явным clamp; проверяются 99 999 размеров.
- Headless egui: настоящий PDF растр рисуется при 50%, 125%, 400%, две страницы,
  кеш ≤2, сохранение/текстовый экспорт/PDF-печать не активируются.
- Готовый смешанный PDF из прежних артефактов открыт только для чтения новым
  reader, без запуска печати. Обе полученные картинки просмотрены: кириллица,
  картинка, таблица и номера страниц видимы. Это QA нового reader, не отложенная
  ручная приёмка recovery/печати.

Тесты и пути: `tests/search_formats.rs`, `tests/pdf_security.rs`, unit/controller
тесты; `manual_phase4_artifacts/search-rc3/`, `manual_phase4_artifacts/pdf-rc4/`.
GUI с настоящими окнами/диалогами ещё NOT VERIFIED; см. `PHASE4_FIND_PDF.md`.

## Граница гарантий

Отсутствие исполнения активного содержимого — свойство выбранных путей программы,
а не антивирусная сертификация. Не исключаются неизвестные уязвимости нативного
PDF/CFB/ZIP/image-парсера, исчерпание ресурсов или ошибки ОС. Windows следует
обновлять; PDF parser работает в потоке процесса, не в отдельной OS-песочнице.
Ограничения файла/страниц/растра не являются доказательством защиты от любого
специально повреждённого документа. Копия DOCX/recovery не очищается от макросов
и вложений: в другой программе они могут иметь другое поведение.

Описание используемого native API:
[Microsoft PdfDocument](https://learn.microsoft.com/en-us/uwp/api/windows.data.pdf.pdfdocument?view=winrt-26100),
[Microsoft PdfPage.RenderToStreamAsync](https://learn.microsoft.com/en-us/uwp/api/windows.data.pdf.pdfpage.rendertostreamasync?view=winrt-26100).
Сами эти ссылки не являются обещанием безопасности; поведение приложения
обосновано кодом и выполненными проверками выше.
