# Проверка восстановления текста — 25.10.2026

Сборка: `LiteOffice-Compact.exe` (0.8.0-rc.22, compact UI, RU/EN).
Окружение: Windows 11, масштаб 125 %, отдельная папка `C:\DHW\.tmp\lo-recovery-check`,
чтобы не затронуть рабочие каталоги проекта. Язык интерфейса — русский.

Проверялись четыре сценария из Phase 4. Ниже — что именно сделано, что
наблюдалось и чем это подтверждено. Ручные действия выполнялись в реальном
окне; там, где нативный диалог/клик не автоматизировался, использован
автотест с реальными файлами и отдельным процессом.

## 1. Новый TXT: правка → kill → restore → Save As

**Ход.** Запуск `LiteOffice.exe --blank-text`; в пустом текстовом окне набрана
строка, через 2–3 секунды в строке состояния появилось
«Контрольная точка записана; оригинал не изменён». Процесс завершён
`Stop-Process -Force` (эквивалент «Снять задачу» в Диспетчере задач).
Повторный запуск показал диалог «Восстановление после прерванного сеанса»,
«Прерванных сеансов: 1. Активные окна исключены». Нажата
«Восстановить несохранённую копию».

**Наблюдения.**
- До kill: `LiteOffice-recovery\session-<pid>-<id>\` с `lease`, `origin.txt`,
  `snapshot-00000000000000000001.lotext`; внутри снапшота — введённый текст.
- После kill и повторного запуска: тот же сеанс предложен к восстановлению,
  текст восстановлен, чипы «ВОССТАНОВЛЕНО» и «ВОССТАНОВЛЕНИЕ ВКЛ»,
  состояние «Не сохранено», статус
  «Восстановлен несохранённый текст. Требуется «Сохранить как»; оригинал не изменён».
- Save As (`Ctrl+S` → нативный диалог) создал отдельный файл; его содержимое
  совпало с восстановленным текстом (15 байт). После сохранения снапшоты
  сеанса удалены; после обычного закрытия и повторного запуска диалог
  восстановления больше не появился.

**Результат: PASS.** Замечание: клавиатурный ввод шёл при русской раскладке,
поэтому латиница превратилась в «к53/5 5 12345»; на суть проверки не влияет.
Файл, сохранённый через нативный диалог, оказался в папке, которую диалог
открыл по умолчанию; для чистоты он перенесён в тестовую папку, оригинальный
каталог проекта не изменён.

## 2. TXT / MD / RTF из `manual_phase4_artifacts\text-rc11`

**TXT — вручную.** Открыт
`C:\NotOffice\liteoffice\manual_phase4_artifacts\text-rc11\text-test.txt`,
в текст добавлено `999`, дождались контрольной точки, процесс снят. После
перезапуска сеанс восстановлен: текст содержит `999`, в статусе требуется
«Сохранить как».

- SHA-256 исходника до правки и после kill/восстановления совпадает:
  `3F5906941A75999A473ADA09B66AF747BD0ECFD568B2651D239C19914E38A593`.
- Исходный файл не открывался на запись; восстановление идёт только в копию.

**MD и RTF.** Тот же сценарий в автотестах с реальными файлами:
`recovery::tests::forced_text_process_termination_recovers_txt_md_rtf_and_untitled`
и `tests::text_recovery_restore_save_copy_and_cleanup_cover_untitled_txt_md_and_rtf`
— **ok**. Тесты проверяют восстановление всех трёх форматов, сохранение копии,
неизменность оригинала и очистку после Save As.

**Результат: PASS** (TXT — вручную, MD/RTF — тем же сценарием в тестах).

## 3. Два окна: живое окно не предлагается

Автотест `recovery::tests::independent_windows_keep_two_generations_each_and_live_sessions_are_not_offered`
— **ok**: две сессии с разными поколениями, активная (живая) исключается из
кандидатов, вторая остаётся доступной. Дополнительно
`recovery::tests::forced_process_termination_releases_lock_and_preserves_checkpoint`
— **ok**: после гибели процесса блокировка снимается, контрольная точка
сохраняется.

В диалоге восстановления это же поведение видно текстом
«Активные окна исключены».

**Результат: PASS** (автотест; отдельный ручной прогон двух окон не дублировался).

## 4. Очистка: Cancel сохраняет правки, Save As снимает предложение

- `tests::unsaved_close_requires_a_choice_and_cancel_keeps_edits` — **ok**:
  Cancel при закрытии оставляет документ и правки.
- `tests::clean_text_close_after_undo_does_not_offer_a_stale_checkpoint` — **ok**:
  после чистого закрытия устаревшая точка не предлагается.
- `tests::text_recovery_error_pending_empty_edits_and_dont_save_close_keep_correct_state`
  — **ok**.
- `tests::failed_save_and_cancel_keep_recovery_but_explicit_discard_close_removes_it`
  — **ok**.
- Вручную: после успешного Save As и обычного закрытия повторный запуск
  показал стартовый экран без диалога восстановления.

**Результат: PASS.**

## Что осталось за рамками

- Нативные диалоги Windows (Save As, печать) автоматизированы частично;
  путь в поле имени файла не подставился, поэтому сохранение ушло в файл
  по умолчанию. Само поведение Save As (отдельная копия, очистка recovery)
  проверено.
- В каталоге сеанса после очистки может остаться пустой `lease`; снапшотов нет,
  сеанс не предлагается. Это наблюдение, а не отказ сценария.
- Большие/повреждённые файлы, ошибки записи и полная регрессия печати —
  вне этого списка; см. `RELEASE_PROGRESS.md` исходного проекта.
