# LiteOffice 0.8.0-rc.22 — восстановление TXT/MD/RTF после сбоя

Для TXT/MD/RTF добавлены контрольные копии, включая новый TXT без имени.
После прерванного сеанса предлагается восстановить отдельную копию; сохранение
требует Save As, исходный файл защищён. Активные окна не предлагаются для
восстановления. Повреждённый последний снимок заменяется предыдущим валидным;
при отсутствии валидных снимков файлы остаются для разбирательства.
Интервал записи — около двух секунд; успешная запись видна в статусе.

Новое пустое окно сразу готово к набору TXT без щелчка. Ctrl+S предлагает
сохранение; TXT/MD сохраняются в UTF-8, принимаются также UTF-16 файлы с BOM.
Markdown редактируется как исходный текст, без выполнения HTML/скриптов/ссылок.
RTF поддерживается на уровне текста: Unicode, кириллица, абзацы и табуляция;
стили, таблицы, изображения, объекты, колонтитулы не сохраняются. При открытии
RTF исходник защищён: результат нужно сохранить отдельной базовой RTF/TXT/MD
копией. Для текста есть безопасная запись, резервные копии и конфликт сохранения.
Поиск/замена новых текстовых форматов пока отсутствуют. Восстановление таблиц
после сбоя остаётся следующим отдельным этапом.

PDF: Print/Ctrl+P → диапазон From/To, Fit либо масштаб 10–400% (100% — исходный
размер) → системный выбор принтера. Ориентация подбирается по исходной странице.
Печатается растр открытой версии PDF, без исполнения PDF-действий; оригинал не
меняется. Это не векторный экспорт, разрешение растра ограничено 2000 px по стороне.

После `Edit values as XLSX copy…` щёлкните ячейку и вводите текст прямо в сетке.
Tab — следующая колонка, Enter — следующая строка; Shift меняет направление.
Верхняя строка осталась только для размера шрифта и Bold.

Для XLS/XLSX: `Edit values as XLSX copy…`, выбор ячейки, ввод её буквального
текста прямо в ячейке, размер шрифта (целые 6–72 pt), Bold, все листы,
Save As XLSX и последующее Ctrl+S. Исходник защищён, повторное сохранение делает
резервную копию `.xlsx.bak`; внешние изменения блокируют перезапись.

Это явная копия значений: числа/даты/формулы экспортируются как отображаемый
текст. Формулы не вычисляются; исходные числовые форматы, таблицы, диаграммы,
разметка и стили сверх поддерживаемых размера/жирности не переносятся.
Восстановление после сбоя для таблиц пока отсутствует; это показано в UI.
Полная поддержка XLS/XLSX и Phase 4 остаются PARTIAL.

Для DOC доступна кнопка «Edit as DOCX…»: редактирование восстановленного текста,
размера шрифта, поиск/замена, Undo/Redo; сохранение в отдельный DOCX. Исходный DOC
защищён. Изображения с известной привязкой переносятся после соответствующего
абзаца, остальные — в конец. Исходные стили и таблицы Word не восстанавливаются;
переносы строк становятся абзацами. Полное требование DOC/XLS остаётся PARTIAL.

В rc.7 исправлено положение страницы при увеличении: первый текстовый фрагмент
остаётся доступным для ввода. Tab из поиска открывает поле замены и переводит
туда фокус; Shift+Tab возвращает его в поиск. Эти сценарии проверены в настоящем
окне на копии replace.docx. Дополнительная коррекция видимости при 400% проверена
автоматически. Всего 168 тестов PASS, 6 пропущены; Phase 4 остаётся PARTIAL.

Промежуточный кандидат для проверки сохранения и защиты несохранённых изменений.
Весь Phase 4 ещё не завершён. Принятый v0.7.5 сохранён отдельно:
`C:\NotOffice\releases\LiteOffice-v0.7.5-phase3-accepted.exe`.

## Исправления rc.6

- После открытия DOCX можно сразу вводить текст: курсор однократно ставится
  в начало первого текстового фрагмента, без щелчка/Tab. Find/Replace и другие
  окна не теряют выбранный вами фокус. Это набор текста, не печать на принтер.
- Короткие слова, включая `ЁЖИК` в таблице, измеряются реальным шрифтом, а не
  оценкой по числу букв: последний glyph больше не обрезается. Длинные run,
  превышающие ширину поля, по-прежнему прокручиваются внутри него.
- Пять новых полных headless UI-проверок; всего 164 теста PASS. Нативная ручная
  проверка двух исправлений ещё NOT VERIFIED: `PHASE4_INPUT_RECHECK.md`.
  Остальные проверки rc.5 пользователь сообщил успешными; не требуется заново
  выдавать весь старый ручной набор. Отложенную регрессию не запускали.

## Возможности rc.5, сохранённые в rc.6

- DOCX: Ctrl+H открывает замену. Replace current / Enter в поле замены меняет
  выбранное вхождение, Replace all — весь документ, включая таблицы и слова
  через границы текстовых run. Пустая замена удаляет текст. Операция целиком
  отменяется Undo; Ctrl+Z/Ctrl+Y/Ctrl+Shift+Z вне toolbar-полей управляют DOCX.
- Ctrl+A / Select all → Delete или Backspace теперь удаляет весь выбранный
  DOCX-текст, включая таблицы. Структура таблиц, картинки и формат run остаются;
  Undo возвращает текст. Это выбор текста, а не удаление всех объектов страницы.
  Внутри обычного текстового поля Delete удаляет выделение или символ справа;
  в конце текста без выделения удалять справа нечего (для удаления слева Backspace).
- Исправлены пустые w:t при Save/reopen и сохранение новых крайних пробелов.
  Replace all — одна транзакция, не более 10 000 совпадений (превышение явно
  блокируется), текст замены до 1 MiB, результат до 32 MiB. Многострочные и
  управляющие символы не принимаются. Вставка наследует формат первого run.
- Поля Find/Replace не удаляют и не форматируют документ по Ctrl+A/Delete и не
  откатывают его по Ctrl+Z. Найденный результат и история независимы у окон;
  защита конфликта Save остаётся обязательной. Нативная GUI-приёмка rc.5 ещё
  NOT VERIFIED; тесты и порядок проверки: `PHASE4_REPLACE.md`.
- Обязательный scope согласован в `MANDATORY_FUNCTIONAL_REQUIREMENTS.md`:
  немедленная печать, DOCX/XLSX-экспорт, редактирование/форматирование DOC/XLS
  с экспортом современных форматов, печать PDF с диапазоном/масштабом и полная
  замена. Здесь выполнен только следующий инкремент DOCX; DOC/XLS/XLSX пока
  read-only, печать открытого PDF и современный экспорт остальных форматов
  ещё не реализованы. Отложенная ручная регрессия не выполнялась.

## Новое: поиск и PDF

- Ctrl+F — единый буквальный поиск в DOC/DOCX/XLS/XLSX. Enter/F3 — далее,
  Shift+Enter/Shift+F3 — назад, Escape в поле поиска — очистить и снять фокус.
  Считаются отдельные вхождения; DOCX ищется также через границы фрагментов
  форматирования и в таблицах. Сравнение — Unicode lowercase без нормализации
  и полного case-folding; пробелы по краям запроса отбрасываются. Лимит — 10 000
  переходов, при превышении показан `+ (limit)`. Подсветка — на уровне
  фрагмента/абзаца/ячейки, точное вхождение отмечено `[скобками]` в контексте внизу.
- Поиск в XLS/XLSX охватывает все импортированные листы/ячейки, включая AD500.
  Переход переключает лист и ограниченную область просмотра, не создавая
  неограниченную сетку. Поиск/прокрутка не меняют исходник или dirty-состояние.
- PDF открывается через Open/Ctrl+O, Recent, CLI и drop как **read-only raster
  viewer**: страницы, масштаб 50–400%, прокрутка. Используется системный
  Windows.Data.Pdf (Windows 10/11), без Word, браузера и отдельной DLL-установки.
  Файл читается в ограниченный immutable buffer; рендер — в отдельном MTA-потоке.
  До 64 MiB и 2000 страниц, кеш двух изображений, длинная сторона растра до
  2000 px. При большом увеличении возможна пикселизация. Поиск/копирование
  PDF-текста, редактирование, печать PDF и пароли пока не реализованы. Метаданные
  открываются синхронно с ожиданием до 10 секунд; максимум производительности
  на тяжёлых PDF не измерен. Растризация не меняет исходный PDF.
- **Документные макросы/скрипты не поддерживаются и не включаются.** Нет VBA,
  XLM, DDE, JavaScript/XFA-исполнителя; PDF показывает только пиксели, без действий
  ссылок, форм, Launch/OpenAction и открытия вложений. Формулы таблиц читаются
  как сохранённые значения, не вычисляются. Скриптовые/macro-enabled расширения
  не принимаются; внешний worksheet relationship отвергается.
- Это не антивирус и не очистка документов: неиспользуемые части DOCX, включая
  активные данные, могут сохраняться в копии/recovery для совместимости.
  При открытии в другой программе действуют её правила. Подробная проверка и
  ограничения: `SECURITY_ACTIVE_CONTENT.md`; чек-лист: `PHASE4_FIND_PDF.md`.

## Сохранение в новом кандидате

- **Save / Ctrl+S** сохраняет открытый DOCX в его текущий путь.
- **Save As / Ctrl+Shift+S** предлагает новый путь и делает его текущим для
  последующих Save. Отмена сохраняет несохранённые изменения в окне.
- Перед заменой существующего файла сохраняется отдельный `.docx.bak`;
  существующие резервные копии не перезаписываются.
- После успешного сохранения обновляются путь и контрольная версия документа;
  повторный Save не считается внешним изменением.
- При внешнем изменении исходного DOCX запись блокируется: можно сохранить
  копию, перечитать файл с явным отказом от своих правок или отменить.
  Копия собирается из пакета, открытого в этом окне, включая изображения,
  связи и неизвестные части. Внешний файл не подмешивается к старым правкам.
- Закрытие окна и открытие другого документа при несохранённых правках требуют
  выбора **Save / Don't save / Cancel**. Ошибка записи не разрешает закрытие.
- Для редактируемого DOCX добавлены отдельные проверенные recovery-снимки рядом
  с exe, без изменения исходника. При изменениях запись выполняется примерно раз
  в две секунды работающего UI; правки после завершённого снимка могут потеряться.
  `Recovery write FAILED` означает, что новые правки пока только в памяти.
- После запуска предлагаются Restore / Discard (с подтверждением) / Later.
  Работающие окна исключаются по OS file lock. Restore не удаляет снимок;
  Ctrl+S для восстановленного документа вызывает Save As. Только успешный Save
  или явный отказ удаляет recovery-содержимое. Сохранять внутри recovery нельзя.
- Проверяются CRC всех ZIP-частей. При повреждении последнего снимка возможен
  откат к предыдущему с предупреждением; неполные `.tmp` не открываются.
  Это защита от сбоя процесса, не гарантия от отказа диска/отключения питания.
  Копии локальные, не зашифрованы; храните exe/recovery в доверенной папке.

DOC остаётся приблизительным просмотром восстановленного текста/изображений,
XLS/XLSX — просмотром без редактирования. Запись этих исходных форматов не
предлагается. Вывод офисных документов в PDF остаётся через Windows Print to PDF;
новый PDF-reader отделён от этого конвейера. Save/Save As и защита закрытия/конфликта
приняты на rc.2; recovery-пункты 1–5 приняты пользователем на rc.2. Отложенная
регрессия recovery остаётся NOT VERIFIED и по просьбе пользователя не запускалась.
Новый поиск и нативный PDF GUI требуют ручной приёмки; Phase 4 остаётся PARTIAL.

Чек-лист: `PHASE4_SAVE_PROTECTION.md`. Версия в заголовке берётся из
`CARGO_PKG_VERSION`. Новый exe: `C:\NotOffice\LiteOffice-v0.8.0-rc.22.exe`.
Recovery-чек-лист: `PHASE4_CRASH_RECOVERY.md`.
Принятый v0.7.5 при экспорте кандидата не заменяется.
Проверенный rc.2 сохранён как `releases\LiteOffice-v0.8.0-rc.2-recovery-checkpoint.exe`.
Промежуточные корневые exe убираются только после проверки нового экспорта;
документы, recovery, архивы исходников и `target` не очищаются.

Проверки: `cargo fmt --check`, `cargo check --all-targets`,
`cargo test --all-targets`, `cargo clippy --all-targets -- -D warnings`,
`cargo build --release`, `git diff --check`.

## Changes

- View zoom expanded from 50–180% to **50–400%** (including persisted settings).
- `−` / `+` adjust zoom in 25 percentage-point steps.
- Editable percentage field and quick presets `125%` and `100%`.
- Default zoom **125% only if no valid saved zoom is present**. Existing preferences are respected.
- Zoom is view-only; it does not change DOCX font sizes, print mode, or resulting PDF.
- One additional unit test for bounds and invalid values.

## Known limitations

- Legacy DOC text and bitmap content may not follow identical typography scaling; this patch does not change its approximate layout architecture.
- At 250–400%, horizontal scrolling is expected with page-width layout. Images remain restricted to their page's available width.
- Since Rust for Windows/MSVC is unavailable in the preparation environment, `cargo check` and actual UI behavior must be verified on Windows.

## Smoke test

1. Open the large shampoo analysis `.doc`.
2. Try `125%`, `200%`, `300%`, `400%`; verify increased onscreen page size and text legibility.
3. Exit and reopen LiteOffice; the chosen zoom should persist.
4. Print to PDF at two zoom levels; PDFs should retain page settings and page count for the same print settings.
