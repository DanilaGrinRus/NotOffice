## Контракт и ограничения

- Только редактируемый DOCX. DOC/XLS/XLSX остаются read-only; восстановления
  несохранённых ручных DOC image-layout настроек здесь не добавлено.
- Папка `LiteOffice-recovery` рядом с запущенным exe. Для экспортированного билда
  это `C:\NotOffice\LiteOffice-recovery`. Ошибка доступа видна в строке состояния.
  Данные локальные, не зашифрованы, права наследуются от выбранной папки.
- Отдельная session-папка и OS file lock для каждого окна. При старте активные
  сессии и уже предложенные другим окном копии пропускаются; PID reuse не влияет.
- Первое изменение запускает запись, дальнейшие изменения проверяются примерно
  каждые две секунды работающего UI (не таймер реального времени). Запись DOCX
  синхронная; скорость на предельно больших пакетах пока не измерена. Возможна
  потеря правок после последнего завершённого снимка, особенно при ошибке записи.
  Статус `Recovery checkpoint saved` относится к последнему завершённому снимку.
- Сборка из неизменяемого открытого пакета, sync файла, повторное открытие полного
  DOCX, сверка модели и CRC всех ZIP-частей. Только затем rename публикует новую
  неизменяемую generation. Исходник и его fingerprint не меняются. Хранятся два
  последних исправных поколения; замена старого — только после проверки нового.
  После fallback ротация не заменяет исправного предшественника повреждённым.
- При повреждении последнего поколения проверяется предыдущее; показывается
  предупреждение. Неполные/temp-файлы не считаются опубликованными снимками.
  Если оба повреждены, ошибка сохраняет файлы для дальнейшего разбора.
- Restore оставляет recovery на диске; закрытие восстановленного окна всё ещё
  требует Save / Don't save / Cancel. Ctrl+S вызывает Save As с именем `*-copy.docx`,
  исходник автоматически не перезаписывается. Сохранение в recovery запрещено.
- Later / закрытие стартового диалога ничего не удаляют. Discard требует второго
  подтверждения. После успешного Save или явного Don't save / успешной замены
  документа удаляются только принадлежащие сессии payload-файлы. Ошибка Save,
  Cancel и неудачное Open сохраняют recovery. Lease-only каталоги остаются
  намеренно, чтобы не создавать гонку замены lock-файла; это не забытые документы.
- При нескольких найденных сессиях Restore открывает выбранную первую; остальные
  остаются доступны новому независимому окну либо следующему запуску.
- Reparse-point каталоги и symlink-снимки не обходятся при поиске сессий. Общие
  ограничения DOCX/ZIP сохраняются. Макросы/скрипты не выполняются.
- Сбой процесса проверяется отдельно от отключения питания, повреждения диска
  или принудительного удаления recovery-папки: последних гарантий здесь нет.

## Автоматические сценарии

Снимок/повторное открытие, удалённый исходник, Unicode, неизменность исходника,
сохранность неизвестных частей, нескольких окон и двух поколений; malformed ZIP,
прерванный temp, fallback, CRC повреждённой неизвестной части, явный discard,
таймер/ошибка записи, Cancel/ошибка Save, неудачный Open, успешный discard+Open,
пост-save очистка. Смешанная фикстура проверяет текст, размеры шрифта, изображения,
таблицу/границы, page break и общий print plan после двух последовательных сбоев.

Отдельный тест запускает принадлежащий ему дочерний процесс, ждёт записанного
снимка, проверяет исключение живого окна, принудительно завершает процесс и
проверяет освобождение блокировки/восстановление. Это не ручная приёмка GUI.

Целевой тест CRC неизвестной части сначала действительно падал, затем прошёл
после добавления полной потоковой CRC-проверки. Первый прогон rename-тестов
блокировался песочницей Windows (os error 5); повтор вне песочницы прошёл.
Отдельный тест сначала воспроизвёл потерю исправного предшественника при ротации
после fallback; после исправления ротации проходит и этот сценарий. Статус
`Recovery pending` не выдаёт ещё не записанные правки за завершённый checkpoint.

## Ручной короткий набор

Используйте `C:\NotOffice\LiteOffice-v0.8.0-rc.2.exe` и копию синтетической фикстуры
`C:\NotOffice\liteoffice\manual_phase4_artifacts\recovery-test.docx`, не личные файлы.
Завершайте в Диспетчере задач только конкретный процесс нового тестового окна,
не все LiteOffice сразу. Не отключайте питание компьютера.

1. **Сбой:** добавьте `CRASH-Ё-111`, не сохраняйте; дождитесь
   `Recovery checkpoint saved` после последней правки (при необходимости 3–5 с).
   Завершите процесс через Диспетчер задач. После запуска — Restore; текст,
   размер шрифта, таблица и картинка на месте, `*` виден, исходник не изменён.
2. **Отложить и повторный сбой:** создайте такой же сбой; после запуска Later,
   закройте/запустите — предложение осталось. Restore, затем снова завершите
   процесс без Save: при следующем запуске копия снова предлагается.
3. **Save As и Cancel:** в восстановленном окне Ctrl+S должен открыть Save As.
   Cancel сохраняет текст/recovery; новый запуск после сбоя снова предлагает
   копию. Затем сохраните вне recovery под новым именем, закройте и запустите:
   эта сессия больше не предлагается, исходник не затёрт, копия открывается.
4. **Явный отказ:** отдельный прогон — Discard selected recovery, No сохраняет
   предложение; затем Discard + Yes удаляет только выбранную сессию. В отдельном
   восстановленном окне обычное закрытие: Cancel сохраняет, Don't save удаляет
   его recovery. Последующий запуск не предлагает отвергнутую сессию.
5. **Два окна:** оба меняют копию одного DOCX без Save, дожидаются снимка. Запуск
   третьего не предлагает живые окна. Завершите только A: новое окно предлагает A,
   но не B; восстановите. B продолжает работать. Проверьте прежний конфликт Save.
6. **Регрессия:** повторный Save, Save As, dirty close/open, печать восстановленной
   копии в PDF — изображение, границы таблицы, кириллица и номера страниц на месте.

Если сценарий не удалось выполнить — NOT VERIFIED, не PASS. Ручная ошибка
недоступного пути из Phase 4A также не становится PASS автоматически.

Итоги команд, размер и SHA-256 экспортированного exe — в `RELEASE_PROGRESS.md`.
