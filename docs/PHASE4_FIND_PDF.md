## Проверить на новом билде

Билд: `C:\NotOffice\LiteOffice-v0.8.0-rc.4.exe`.

1. В каждом из `manual_phase4_artifacts/search-rc3/search.docx`, `search.doc`,
   `search.xlsx`, `search.xls`: Ctrl+F, запрос `ёжик` — 3 вхождения без учёта
   регистра. DOCX включает слово, разбитое на два форматированных фрагмента,
   и текст таблицы. Find не ставит `*` и не изменяет исходный файл.
2. Enter/F3 и Shift+Enter/Shift+F3, кнопки ◀/▶ — переходы с зацикливанием,
   счётчик/контекст `[вхождения]` обновляются. После перехода вручную прокрутите
   документ: он не должен сам возвращаться к совпадению каждый кадр. Повторные
   вхождения в одном фрагменте/ячейке имеют общий фон, но разные счётчик/контекст.
3. В XLS и XLSX второе вхождение переключает на `Notes!AD500`, то есть за пределы
   прежних 200 строк/26 столбцов; третье — второе слово той же ячейки. Затем
   переход возвращается на `Main!A1`. Пустой/несуществующий запрос — 0/0, Escape
   в поле очищает запрос, Ctrl+A в Find не выбирает текст DOCX для форматирования.
4. Откройте обычный PDF через Ctrl+O, Recent, drop, CLI либо Open in new window.
   Страницы/номер страницы, 50–400%, прокрутка; исходный PDF не изменяется.
   PDF — только растр: нет Save/редактирования, поиска/копирования текста или
   печати PDF. Для нового reader можно использовать `manual_phase4_artifacts/pdf-rc4/plain.pdf`.
5. На тестовом DOCX с несохранёнными правками попробуйте открыть PDF: Save /
   Don't save / Cancel действуют как прежде. Выбор `pdf-rc4/broken.pdf` оставляет
   предыдущий документ/правки с понятной ошибкой. После успешного PDF → DOCX
   редактор снова работает. Скрипты/макросы нигде не предлагают включить.

Не открывайте активную fixture в другой программе и не запускайте тестовый `.cmd`.
Безопасность и пределы PDF-reader описаны в `SECURITY_ACTIVE_CONTENT.md`.
Формат PDF и активное содержимое добавлены по явному запросу пользователя
2026-10-24. Это не переход к следующей фазе и не заявка на v1.0.
