## Форматирование DOCX

- Добавлены жирный, курсив, подчёркивание и зачёркивание для выделенного run/всего текста DOCX.
- Форматирование сохраняется в OOXML (`w:b`, `w:i`, `w:u`, `w:strike`) и отображается в редакторе.
- Добавлены простые маркированные/нумерованные списки: префиксы вставляются в текст, Enter продолжает список.

- Цвета ячеек и формулы хранятся в памяти текущей сессии; в XLSX сохраняется результат/значения, не формула и не цвет.

## Исправления таблиц

- Округление отображения больше не меняет сохраняемое значение: результат формулы хранится с полной точностью, а настройка знаков после запятой только отображает его.
- Заполнение продолжает арифметическую последовательность по разности последних двух значений (1,2,3 → 4,5).
- Вставка строк/столбцов переносит форматирование вместе с ячейками; ключи форматов синхронизируются перед сохранением XLSX.
- Формулы при вставке строки/столбца сдвигаются только на текущем листе.

- Исправлена потеря малых чисел: при хранении используется полное `f64`-представление (`1/10^16` сохраняется как `0.0000000000000001`), округление остаётся только экраном.
- Undo вставки строки теперь восстанавливает и `book.formats`, и `editor.formats`; сохранение сохраняет жирное начертание.
- Undo вставки строки/столбца восстанавливает карту исходных формул; выражения больше не остаются привязанными к сдвинутой ячейке.

- XLSX: Shift+клик/диапазон, заполнение с предпросмотром и фиксацией только по отпусканию мыши, удаление диапазона, контекстное меню, верхнее поле значения.

## Сохранение цветов и формул

- `CellFormat` расширен заливкой; writer пишет `fills`/`fillId` в `styles.xml`, parser читает обратно.
- Формулы сохраняются как `<f>` с кэшированным значением `<v>` и читаются при открытии; сохраняются только простые формулы безопасного синтаксиса, внешние/активные формулы не переносятся.

- Добавлено протягивание диапазона мышью по неактивным ячейкам, Shift+клик, верхнее поле значения и предпросмотр заполнения; Delete очищает диапазон/ячейку. Полное протягивание мышью от активной ячейки ограничено текстовым курсором.

## События буфера

- Ctrl+C/Ctrl+V для строк, столбцов и диапазонов теперь обрабатывают не только `Key::C`/`Key::V`, но и egui-события `Event::Copy`/`Event::Paste`.
- Добавлен регрессионный тест: выделенный диапазон копируется событием Copy и вставляется событием Paste в другую строку.

- Shift+клик по номерам строк/буквам столбцов расширяет выделение на несколько строк/столбцов (диапазон).
- Клик по пустому месту вокруг таблицы снимает выделение строки/столбца/диапазона.
- Ctrl+C/Ctrl+V строк/диапазонов проверены тестами Key-событий и egui Copy/Paste-событий.

- Верхняя панель XLSX перестроена: строки редактирования и действий разделены; копирование/вставка/добавление строк и столбцов сгруппированы в меню «Строка», «Столбец», «Буфер», закрепление — в «Вид».

- Ctrl+V при фокусе в текстовом поле больше не перехватывается таблицей; ячейки таблицы обрабатываются только при фокусе в редакторе ячейки или без текстового фокуса.
- `Event::Paste` с текстом из внешнего приложения заменяет внутренний буфер NotOffice, поэтому старые скопированные данные больше не вставляются.

- Два поля в верхней панели больше не дублируют значение: формула показывается только в поле формулы, значение — в поле значения.
- Выделение строк/столбцов и диапазонов имеет приоритет над пользовательской заливкой; подсветка не теряется на цветных ячейках.
- Ползунок прокрутки увеличен и затемнён.
- Горизонтальная прокрутка учитывает `smooth_scroll_delta.x` от тачпада, а не только raw-события.
- Заполнение двух выделенных чисел продолжается по разности (1,2 → 3,4,5); добавлен регрессионный тест.

- При выделении диапазона фокус редактора снимается, поэтому Ctrl+C/Ctrl+V работают с диапазоном, а не с текстом активной ячейки.
- Поле формулы очищается для обычных значений; дублирование значения в двух верхних полях устранено.

- Снятие фокуса при выделении диапазона выполняется только для редактора активной ячейки и больше не отбирает фокус у поиска или других полей.

## Мини-аудит безопасности

Исправлено: переполнение чтения CF_UNICODETEXT ограничено `GlobalSize`; XLSX-парсер ограничивает число ячеек, общих строк, формул и стилей, проверяет границы A1 и защищён от целочисленного переполнения при разборе ссылок.

Остаточные риски: reparse-point гонки в каталоге восстановления; нативный PDF-рендерер Windows; локальный подмен print-manifest; зависимость от crates.io без cargo-audit; `panic=abort` превращает любой оставшийся panic в завершение процесса.

- HTML-экспорт таблицы ограничен 5000 строками и 128 столбцами, чтобы разреженная ячейка XFD1048576 не вызывала гигантский цикл.
- XLS/ODS: проверка размера файла 64 МиБ, 64 листов, 500000 ячеек, размеров диапазона; значения ячеек ограничены 1 МиБ.
- DOCX: лимиты 100000 абзацев, 500000 фрагментов, 16 МиБ текста, 1 МиБ на фрагмент.
- CSV/TSV: ячейка ограничена 1 МиБ.

- Восстановление: удаление сессии больше не использует рекурсивный remove_dir_all; удаляются только известные обычные файлы, затем пустой каталог.
- Печать: helper больше не пишется во временный файл, исходник передаётся дочернему PowerShell через окружение; подмена helper.ps1 исключена.

- Print manifest передаётся дочернему PowerShell через stdin; job.txt и helper.ps1 во временном каталоге больше не создаются.
- `recent.txt` ограничен 64 КиБ, UNC-пути не проверяются через файловую систему при загрузке.
- Sidecar раскладки DOC ограничен 128 КиБ до чтения.

- DOCX: активные части (vbaProject, embeddings, ActiveX, customUI, glossary/OLE) не переносятся обычным сохранением; пакет сохраняется без них.
- Release: `panic=abort` заменён на unwind; `update` ловит панику и оставляет окно открытым с контролируемым статусом.
- Print: manifest и helper передаются через stdin/окружение; временные job.txt/helper.ps1 не создаются.
- Добавлен CI-workflow `security.yml` с `cargo audit`.

- Заполнение: цель протягивания сохраняется между кадрами и при отпускании мыши применяется даже если `interact_pos` уже пуст; для двух чисел 1,2 продолжение 3,4,5 покрыто тестом.

- DOCX: убрано собственное выделение слова по двойному клику — используется нативное выделение только слова.
- XLSX: маркер заполнения перенесён в нижний правый угол выделенного диапазона, поэтому вниз тянут именно нижнюю ячейку.
- XLSX: копирование строк/столбцов/диапазона переносит формат ячеек вместе со значениями, размер шрифта при вставке сохраняется.

## Изоляция парсеров (этап 1)

- XLSX/XLS/CSV/DOCX открываются дочерним процессом NotOffice (`--xlsx-parse-worker`, `--xls-parse-worker`, `--csv-parse-worker`, `--docx-parse-worker`) с таймаутом 30 секунд.
- Родитель получает только сериализованную модель/изображения; падение или зависание парсера не завершает UI-процесс.
- DOCX после изоляции модели повторно проверяет ZIP/raw package в родителе перед сохранением.
- PDF и legacy DOC пока не изолированы; release остаётся panic=unwind.

- Legacy DOC также открывается дочерним процессом `--doc-parse-worker`.

- Сохранение DOCX вынесено в дочерний процесс `--docx-save-worker`; модель передаётся JSON, запись/проверка пакета выполняются вне UI-процесса, после успеха пакет переоткрывается worker-процессом.

- Сохранение XLSX вынесено в `--xlsx-save-worker`: origin/saved-path/sheets/formats/formulas передаются JSON; запись и проверка выполняются дочерним процессом, после успеха книга переоткрывается worker-процессом.

- PDF: проба страниц и рендер PNG выполняются дочерними процессами `--pdf-probe-worker`/`--pdf-render-worker`; родитель получает только размеры и PNG.
- Печать PDF в приложении использует изолированный PDF-session; тестовые API сохраняют нативный путь.

- Recovery: восстановление DOCX/XLSX/текста выполняется дочерним процессом `--recovery-restore-worker`; родитель получает сериализованную модель/текст.
